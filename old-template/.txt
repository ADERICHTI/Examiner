Routing and authentication rules:
- If a URL includes a test id query value, preserve that id across navigation.
- If the user is not logged in, redirect them to the auth page.
- When the user is signed in, their email is the document id in the users collection.
- For authenticated users, check the testsTaken object in their user document.
- If testsTaken contains the current test id and its value is true, redirect the user to the submissions page.
- If the test id is not present in testsTaken, or its value is false, continue with the normal test flow.

Student test-start rules:
- When an authenticated user enters a student id and name and clicks Start Test:
  - Check the {testid} collection for a document whose doc id is the student id.
  - That document is created when the user starts the test successfully.
  - Its testTaken field starts as false.
  - If the document exists and testTaken is true, redirect the user to the submissions page(telling the user a submission as been made under that id for this test).
  - Otherwise keep the user on the normal test page so they can take the test.

Test data rules:
- There is a tests collection that stores metadata for every test created by the admin.
- Each test id for every test created by the admin should be the admin-entered id plus a random unique suffix, for example vg63f127.(during creation)
- This collection is where the id query value in the URL is verified.
